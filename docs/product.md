# 产品

## 定位

Oriel 是单用户的混合信息流阅读器：订阅原生 RSS 和 RSSHub，一条时间线混排文章、视频、社交和图片，摘要和翻译按需走用户自己的 OpenAI 兼容接口。它用 Go 和 MyGo 原生 UI，不用 WebView。

Oriel 只负责接收：内容只经订阅进来（RSS、Atom、JSON Feed 和 RSSHub），不登录原站账号，不调用平台的私有接口，也不往外发布内容。新功能先对照这一条，越过它的不做。

## 范围

计划的范围，按 [milestone](https://github.com/yangflow/oriel/milestones) 的顺序逐项落地（规则见 [roadmap](roadmap.md)）：

- 时间线混排四种形态：`article`、`video`、`social`、`image`。形态按源决定，条目跟随源。
- 添加订阅：博客 RSS、YouTube / 哔哩哔哩 / X / GitHub / Telegram / 微博链接，或 RSSHub 路径。
- 文章阅读器：全文抽取，抽不到就显示 RSS 正文并标明不是全文。
- 视频和社交条目显示封面和摘要，点开交给系统浏览器打开原站。没有 WebView，所以不内嵌官方播放器。
- 按需 AI 摘要和翻译，prompt 可全局改，也可按源覆盖。
- 导入、导出 OPML。

不做：多用户、发现台、推荐、高亮笔记、插件、MCP、播客、邮件 inbox、自建播放器、登录原站账号。

## 架构

同一个程序既是服务端又是客户端（见 [ADR 0002](adr/0002-standalone-client-and-server.md)）：

- 服务端负责抓取、正文抽取、存储、AI 调用和清理，并提供 HTTP API。
- 客户端是原生界面，只通过 HTTP API 读写数据。
- 桌面模式在本机启动服务端、只监听 `127.0.0.1`，再打开窗口。无窗口模式只跑服务端，供其他设备上的 Oriel 客户端连接。
- 桌面模式没有首次设置，打开就进时间线。也可以改连另一台电脑上的无窗口模式：填服务端地址和口令登录，口令只在登录时发送，不保存。

## 运行模式

| | 桌面模式 | 无窗口模式 |
|---|---|---|
| 启动 | 打开应用，或不带参数运行 `oriel` | `oriel serve [-data 目录] [-port 端口]` |
| 数据目录 | 系统的用户数据目录：macOS `~/Library/Application Support/Oriel`，Windows `%AppData%\Oriel`，Linux `~/.config/Oriel` | 同左，`-data` 可改 |
| 监听 | `127.0.0.1` 的随机空闲端口，不要口令 | 默认端口 7470。没设口令只听 `127.0.0.1`；设了口令听所有网卡 |
| 口令 | 不用 | 只从环境变量 `ORIEL_PASSWORD` 读，不接受命令行参数，免得出现在进程列表里 |
| 退出 | 关最后一个窗口或退出菜单；服务端随之关闭 | SIGINT 或 SIGTERM，最多等 10 秒让请求完成 |

- 桌面模式只开一个实例。再次打开时，已有的实例把窗口带到前面。
- 同一个数据目录同时只能有一个进程（见「存储」）。桌面模式打不开数据时，用系统语言弹出原生错误框，然后退出。
- 无窗口模式不启动界面事件循环，不加载 GTK 等界面库，可以跑在没有图形环境的服务器上。
- 版本号只写在 `mygo.json`，打包和未打包的程序都从这里读，`/health` 返回它。

### 连接远程服务端

桌面应用默认读写本机的服务端。应用菜单的「连接服务端…」打开连接界面，填地址和口令，改连另一台电脑上的 `oriel serve`。

- 地址没写协议时补 `http://`；没写协议也没写端口时补端口 7470。
- 先请求 `GET /health`：连不上、不是 Oriel、数据库不可写各有一句提示。不要口令的服务端直接连上；要口令的再 `POST /auth/login`，口令为空或不对时提示在口令框下。
- 连上后，服务端地址和会话 token 写进数据目录的 `remote.json`，只有当前用户能读写（0600）。口令只在登录时发送，不写进任何文件。
- 再次打开应用时，用保存的 token 请求 `GET /api/settings` 检查会话。401 时打开连接界面，写明哪个服务端的登录失效了，地址已填好，焦点在口令框；连不上时也打开连接界面，显示连不上。
- 连接界面的「本机」按钮回到本机服务端，删掉 `remote.json`。
- 网络和磁盘操作都在后台做，界面不卡；连接中再点「连接」不会重复发请求。

## 数据模型

时间都是 Unix 毫秒整数。布尔是 `0` / `1`。

### 源

一条订阅。每个源有一个形态：`article`、`video`、`social`、`image`，没有第五种。条目的形态跟随源，条目表里不存形态，改源的形态，条目跟着变。

| 字段 | 说明 |
|---|---|
| `url` | 订阅地址。RSSHub 源为空串。 |
| `rsshub_path` | RSSHub 路径，以 `/` 开头。普通源为空。抓取时拼上当前的 RSSHub 根地址，换实例只改设置。 |
| `title`、`site_url`、`icon_url` | 展示用。 |
| `icon_checked_site` | 上次为找图标而查看过主页的站点地址，见「抓取」。 |
| `kind` | 四种形态之一。 |
| `etag`、`last_modified` | 条件请求用。 |
| `last_fetched_at`、`last_success_at`、`last_error`、`consecutive_failures` | 抓取健康状况。 |
| `fetch_interval_sec` | 默认 900。 |
| `next_fetch_at` | 到期时间。「更新」只把它改成现在，不在请求里抓。 |
| `prompt_summary`、`prompt_translate` | 覆盖全局 prompt，空就用全局的。 |
| `auto_summary`、`auto_translate` | 按源开关，默认关。没有全局开关。 |
| `mute_keywords` | 按行分隔的屏蔽词，见「屏蔽词」。 |
| `paused` | 暂停的源不抓，也不能标到期。 |

`url` 和 `rsshub_path` 合起来唯一，同一订阅不能加两次。

### 条目

源里的一条内容，按 `(source_id, guid)` 去重；没有 guid 时用规范化后的条目 URL。删源时条目一起删。

| 字段 | 说明 |
|---|---|
| `guid`、`title`、`url`、`author`、`published_at` | 来自订阅。`published_at` 只用来展示，会被重新发布覆盖。 |
| `rss_summary`、`rss_content_html` | 订阅里的摘要和正文。 |
| `extracted_html`、`extract_status`、`extract_attempts` | 抽取的正文。状态 `pending` → `ok` / `failed`；非文章形态为 `skipped`。 |
| `kind` | 所属源的 `kind` 的副本，只为让「按形态」和「未读」的时间线走索引；数据库触发器在新条目写入和源改形态时同步，不由接口读写。 |
| `thumbnail_url`、`duration_sec`、`platform` | 视频和社交的展示信息。 |
| `language` | 条目文字的语言，BCP 47 码：ISO 639-1 的两个字母（`en`、`de`、`ja`……），中文分 `zh-Hans` 和 `zh-Hant`，没有两字母码的语言用三字母码。可为空（`NULL`）：文字太短或检测没有把握时不写，不猜。见「语言检测」。 |
| `images` | JSON 数组，每项 `{ "url", "width"?, "height"? }`，没有图为 `[]`。 |
| `is_read`、`read_at`、`starred` | 阅读状态。收藏的条目不被保留期限清理。 |
| `search_text` | 抽取正文的纯文本，进全文索引。 |

时间线按 `created_at, id` 排序和分页，不用 `published_at`。

### 语言检测

抓取写入条目时，用纯 Go 的检测库（`github.com/abadojack/whatlanggo`，MIT）判断条目的语言，不联网：

- 样本是标题加上订阅里摘要或正文的纯文本，最多取前 3000 个字符。字母少于 20 个，或检测库认为不可靠（置信度不高于 0.8），语言就留空。
- 检测成中文时，数只有繁体或只有简体才用的常用字：繁体字更多为 `zh-Hant`，否则（含相等）为 `zh-Hans`。
- 文章形态抽取到全文后，用全文重新检测一次，检测出来才覆盖；检测不出来保留原值。
- 订阅内容之后变了，条目被重新写入时语言一并更新；检测不出来保留原值。已有的旧条目不补，语言保持为空，直到内容变化。

语言用在两处：目标语言（`aiLanguage`）和条目语言相同的条目，自动翻译不排队（摘要照常）；阅读界面不显示这样的条目的「翻译」按钮，并按条目语言选正文的行高：中文和日文用较高的行高，其他已知语言用拉丁文的；语言为空时按标题和正文有没有汉字判断。语言为空的条目照旧可以翻译。

### AI 结果

一个条目的一种 AI 结果一行，任务是 `summary`（摘要）或 `translation`（翻译），按 `(entry_id, task)` 唯一。删条目时一起删。

| 字段 | 说明 |
|---|---|
| `status` | `pending`（排队或进行中）→ `ok` / `failed`。 |
| `text` | 结果，纯文本，段落之间空一行。失败时保留上一次成功的结果。 |
| `error` | 失败的错误码，见「AI 接口」。 |
| `attempts` | 自动处理试过几次，满 3 次不再自动重试。 |
| `requested` | 是用户要的（`1`）还是自动排的（`0`）；用户要的先处理。 |
| `fingerprint` | 输入的指纹：模型、生效的 prompt、目标语言和送去的原文的 SHA-256。 |
| `model` | 生成结果的模型。 |
| `updated_at` | 最近一次排队或处理的时间。 |

结果是派生内容，不改条目的 `updated_at`，不进全文索引。

### 设置和会话

设置是键值表。API key 存在这里，接口不下发，只回「已配置 / 未配置」。

会话一行一台设备：token 的 SHA-256、User-Agent、创建时间、最近使用时间。不存 token 原文。

## 存储

- SQLite，一个文件 `oriel.sqlite`，WAL，开外键。驱动是纯 Go 的 `modernc.org/sqlite`（见 [ADR 0003](adr/0003-pure-go-sqlite.md)）。
- 全文检索 FTS5，分词 trigram，列为标题、RSS 摘要、`search_text`。由触发器和条目表同步。
- 迁移是内嵌的 SQL 文件，按 `PRAGMA user_version` 逐个执行，每个一个事务。只加新迁移，不改已发布的。
- 同一个数据目录只能有一个 Oriel 进程：打开数据库时对旁边的 `oriel.sqlite.lock` 加系统文件锁，第二个进程直接报错。进程崩溃时系统会释放锁。
- 数据库文件只有当前用户可读写（`0600`），里面有会话和 API key。
- 数据目录里还有代理图片的缓存 `image-cache/`（见「图片代理」），是可再生的，删掉不影响数据。

## 抓取

抓取循环跑在服务端进程里，两种运行模式都有，没有单独的 worker。

1. 每 15 秒取到期（`next_fetch_at` 已到）且未暂停的源，最多 4 个，同时抓。
2. 带 ETag / Last-Modified 条件请求。超时 25 秒，响应最大 8 MiB，User-Agent `Oriel/<版本>`。
3. RSSHub 源用设置 `rsshub_base_url` 加 `rsshub_path` 拼地址，换实例只改设置。没设根地址时这次抓取记为失败。完整的 RSSHub 地址（例如 `https://rsshub.app/bilibili/hot-search`）按普通源抓，用不到根地址；根地址只给只填路由的订阅用。
4. 解析 RSS、Atom 和 JSON Feed，按 `(source_id, guid)` 写入。相对链接按订阅地址补全，只留 http 和 https 地址。
5. 同一次抓到的条目从最后一条往前写，`created_at` 相同时新的条目 `id` 大，在时间线上排前面。
6. 已有的条目只在内容变了时更新，`updated_at` 也只在这时改；已读和收藏不动。
7. 文章形态的新条目 `extract_status` 为 `pending`，其他形态为 `skipped`。
8. Discourse 论坛帖子里引用别人的 `<aside class="quote">` 去掉，免得回帖把别人的话当成自己的正文。
9. 源的标题和站点地址为空时，用订阅里的补上，不覆盖用户改过的。
10. 源的图标（`icon_url`）为空时找一次：先用订阅里带的图（RSS 的 `<image><url>`、Atom 的 `<icon>` 或 `<logo>`、JSON Feed 的 `icon`），没有就取站点地址的首页，读 `<link rel="apple-touch-icon">` 和 `<link rel="icon">`，apple-touch-icon 优先，其次 PNG，SVG 和 ICO 不要。首页按「正文抽取」的规则取（只连公网地址，经同一个受限客户端）。找不到就留空，站点地址变了之前不再找。

成功（含 304）后按 `fetch_interval_sec` 排下一次，清掉失败计数和 `last_error`。失败时 `consecutive_failures` 加一，原因写进 `last_error`：连续失败 `n ≤ 5` 次时 60 秒后再试，之后 `min(60 × 2^(n−5), 600)` 秒。状态码是 429 或 503 且带 `Retry-After`（秒数或 HTTP 日期）时，下一次不早于它指的时刻，即等待取 `Retry-After` 与上面的时间中较长的，最长 24 小时；值无效、为负或已过去时忽略，按上面的时间排。失败照常计数。Cloudflare 拦截和 RSSHub 路由 404 有专门的说明。

订阅地址是用户自己填的，可以指向本机或内网（例如自建的 RSSHub），不做 SSRF 检查。订阅内容带出来的地址由正文抽取检查（见下一节）。

抓订阅时认 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量，不读系统代理设置。

## 正文抽取

每次抓取之后，同一个循环再取最多 4 条等待抽取的文章，同时抽：先取从没试过的（新的在前），再取失败但没满 3 次的。源后来改成别的形态时，它的条目不再抽。

1. 下载条目链接的网页，超时 25 秒，最大 8 MiB，按响应头和网页声明的编码解码。
2. Discourse 论坛的帖子页只取链接指向的那一楼（`#post_N` 或 `/t/<slug>/<主题>/<N>`，没有就取一楼），并去掉引用块；其他网页用 Readability 取正文。相对链接按最终地址（跟随重定向之后）补全。
3. 成功时 `extract_status` 为 `ok`，写 `extracted_html` 和它的纯文本 `search_text`（进全文索引）；失败为 `failed`。每次都给 `extract_attempts` 加一，满 3 次不再自动重试。
4. 抽取的结果是派生内容，不改条目的 `updated_at`。

条目链接来自订阅内容，不是用户填的，所以只能访问公网地址：

- 检查发生在建立连接的那一刻，对象是实际要连的 IP，所以 DNS 解析和每一次重定向都绕不过去。重定向最多 5 次，只能到 http 或 https。
- 拒绝回环、私有网段（`10/8`、`172.16/12`、`192.168/16`、`fc00::/7`）、链路本地（含云元数据地址 `169.254.169.254`）、组播、`0.0.0.0/8`、`100.64/10`、`240/4`，IPv4 映射的 IPv6 地址按 IPv4 判断。
- `198.18.0.0/15` 不拦：Clash 等代理的 TUN 模式会把所有域名解析到这个网段。
- 直接连接，不走代理：经过代理时看不到真正的目标地址。

## 保留期限

设置 `retention_days`，单位天：`0` 或不设是永久（默认），最大 3650，不是整数的值按永久处理。

- 抓取循环每小时最多清理一次：删除未收藏且过期的条目，已读未读无关。过期按发布时间算，没有发布时间按写入时间。
- 抓取时，发布时间早于保留期限的新条目直接跳过。否则订阅里还留着的旧条目会在清理后被当成新条目抓回来，以未读身份出现在时间线最上面，一小时后又被删掉，如此反复。已经在库里的条目不受影响，等清理删除。

## 鉴权

- 没设口令时，服务端只听 `127.0.0.1`，不校验。桌面模式默认这样。
- 设了口令时听所有网卡，除 `GET /health` 和 `POST /auth/login` 外都要会话。
- 口令不写进日志和数据库。启动时用 PBKDF2-SHA256（60 万轮、随机盐）派生一次，登录时同样派生后用常数时间比较。
- 登录请求的坏 JSON 返回 401，不是字段校验错误。
- 会话放在 cookie `oriel_session`（HttpOnly，SameSite=Lax，30 天；HTTPS 或带 `X-Forwarded-Proto: https` 时加 Secure），或 `Authorization: Bearer <token>`。空闲满 30 天失效。最近使用时间最多一分钟写一次。
- 每次登录是一条设备会话，可以单独退出登录，也可以登出当前会话。

## HTTP 约定

- 只用标准库 `net/http`。JSON 字段用 camelCase。
- 出错时返回 `{ "error": "<代码>" }`，代码是稳定的小写英文，界面据此显示本地化文案。
- `GET /health` 不要鉴权，返回版本、是否要求口令、数据库是否可写。数据库不可写时 503。
- 已有的路由：`POST /auth/login`、`POST /auth/logout`、`GET /api/sessions`（列出未过期的会话，标出当前会话）、`DELETE /api/sessions/{id}`，以及「订阅接口」「时间线接口」「设置接口」「OPML 接口」「AI 摘要和翻译」「图片代理」六节的路由。其余路由随各自的功能加进来，并写进这一节。
- 请求体是 JSON，最大 64 KiB；坏 JSON、多出未知字段或类型不对返回 400 `invalid_body`。

## 订阅接口

都要会话（设了口令时）。源在 JSON 里是一个对象：`id`、`url`、`rsshubPath`、`title`、`siteUrl`、`iconUrl`、`kind`、`fetchIntervalSec`、`nextFetchAt`、`lastFetchedAt`、`lastSuccessAt`（从没有过为 `null`）、`lastError`、`consecutiveFailures`、`promptSummary`、`promptTranslate`、`autoSummary`、`autoTranslate`、`muteKeywords`、`paused`、`unreadCount`、`createdAt`、`updatedAt`。`etag` 和 `last_modified` 只给抓取用，不下发。

| 路由 | 作用 |
|---|---|
| `GET /api/sources` | 列出所有源，按标题（空标题用地址）排序，返回 `{ "sources": [...] }`。 |
| `POST /api/sources` | 添加，返回 201 和新源。新源马上到期，由抓取循环去抓，请求里不抓。 |
| `GET /api/sources/{id}` | 一个源。 |
| `PATCH /api/sources/{id}` | 改字段，只改请求里带的，返回改后的源。 |
| `DELETE /api/sources/{id}` | 删源和它的全部条目，含收藏的，返回 204。 |
| `POST /api/sources/{id}/refresh` | 「更新」：把 `next_fetch_at` 改成现在，返回 204。 |

添加时的字段：`url` 和 `rsshubPath` 恰好给一个，`kind` 必填，`title` 和 `fetchIntervalSec` 可选。标题去掉首尾空白。

- `url` 去掉首尾空白后必须是带主机名的 http 或 https 绝对地址，否则 `invalid_url`。可以指向本机或内网（见「抓取」）。
- `rsshubPath` 去掉首尾空白后必须以 `/` 开头、不以 `//` 开头，否则 `invalid_rsshub_path`。
- `url` 和 `rsshubPath` 都给或都不给时 `invalid_source`。
- `kind` 不是四种形态之一时 `invalid_kind`。
- `fetchIntervalSec` 是 60 到 604800（7 天）的整数，默认 900，否则 `invalid_interval`。
- 同一订阅已经有了，返回 409 `source_exists`。

能改的字段：`title`、`kind`、`fetchIntervalSec`、`promptSummary`、`promptTranslate`、`autoSummary`、`autoTranslate`、`muteKeywords`、`paused`。订阅地址不能改，要换就删了重加。

- 标题改成空串时，下次抓取用订阅里的标题补上。
- 改 `kind` 后条目的形态跟着变（见「数据模型」）；改成别的形态的源不再抽取正文。
- 改 `fetchIntervalSec` 从下一次抓取之后生效；想马上抓就「更新」。
- `muteKeywords` 按行保存，每行去掉首尾空白，丢掉空行。
- 暂停的源「更新」返回 409 `source_paused`。恢复后按原来的 `next_fetch_at` 抓，已经过了就马上抓。
- 源不存在时 404 `not_found`，`id` 不是整数时 400 `invalid_id`。用户改字段时更新源的 `updated_at`；抓取记账不改。

## 时间线接口

都要会话（设了口令时）。条目按 `created_at, id` 从新到旧排，不用 `published_at`（见「数据模型」）。

| 路由 | 作用 |
|---|---|
| `GET /api/entries` | 一页条目，返回 `{ "entries": [...], "nextCursor": "..." }`；没有下一页时 `nextCursor` 为 `null`。 |
| `GET /api/entries/{id}` | 一个条目，多带正文。 |
| `PATCH /api/entries/{id}` | 改 `isRead`、`starred`，只改请求里带的，返回改后的条目。 |
| `POST /api/entries/read` | 「全部已读」「把上面的标为已读」「把订阅标为已读」，返回 `{ "marked": n, "ids": [...] }`。 |
| `POST /api/entries/unread` | 撤销上面三种已读：把请求里的 `ids` 标回未读，返回 `{ "marked": n }`。 |

列表里的条目：`id`、`sourceId`、`sourceTitle`（源的标题，空就用地址）、`kind`（源的形态）、`title`、`url`、`author`、`publishedAt`、`summary`（订阅里的摘要）、`thumbnailUrl`、`durationSec`、`platform`、`images`、`language`（没有为空串）、`extractStatus`、`isRead`、`readAt`、`starred`、`createdAt`。没有的时间和时长为 `null`。单个条目再多带 `contentHtml`（订阅里的正文）和 `extractedHtml`（抽取的正文，没有为空串）。

`GET /api/entries` 的查询参数，都可选，可以组合：

- `source`：只看这个源；`kind`：只看这种形态的源。值不对时 `invalid_source`、`invalid_kind`。
- `unread=1`：只看未读；`starred=1`：只看收藏。其他值当没给。
- `q`：全文检索标题、订阅摘要和抽取的正文。去掉首尾空白后按整段文字匹配，不认检索语法，不分大小写。trigram 分词要求至少 3 个字符，短了返回 `query_too_short`。
- `limit`：一页几条，1 到 100，默认 50，否则 `invalid_limit`。
- `cursor`：上一页的 `nextCursor`，取它之后更旧的一页。是不透明的字符串，客户端不要拼；不对时 `invalid_cursor`。

新条目写在最上面，按游标翻页不会重复也不会漏，翻页时新到的条目要从头再取。

`PATCH /api/entries/{id}`：

- `isRead` 改成 `true` 时记下 `read_at`，已经是已读就不变；改成 `false` 时清空 `read_at`。
- `starred` 改成 `false` 后，过了保留期限的条目在下次清理时删掉。
- 不改条目的 `updated_at`：它只记订阅内容的变化。

`POST /api/entries/read` 的请求体可以为空，字段都可选：`sourceId`、`kind`、`upTo`、`newerThan`。`upTo` 是条目 `id`，只标时间线上它和比它旧的条目，免得把用户还没看到的新条目一起标掉；`newerThan` 也是条目 `id`，只标比它新的条目（不含它自己），和 `upTo` 一起用就标出一段：比 `newerThan` 新、不比 `upTo` 新。两个条目不存在时都是 `not_found`。`ids` 是这次从未读变成已读的条目，给撤销用。

`POST /api/entries/unread` 的请求体是 `{ "ids": [...] }`，最多 10000 个，空或超出时 `invalid_ids`。只改其中已读的条目：清空 `read_at`，收藏不动；不存在的 `id` 跳过，不报错。

### 屏蔽词

源的 `muteKeywords` 每行一个屏蔽词。条目的标题或订阅摘要里包含其中任何一个，就算被屏蔽：

- 按子串匹配，不分大小写，不认通配和正则。只看标题和订阅摘要（纯文本），不看正文和抽取的正文。
- 被屏蔽的条目不出现在 `GET /api/entries` 的任何结果里，检索也一样；不计入源的 `unreadCount`；「全部已读」不改它们。
- 收藏的条目不屏蔽：用户特意留下的，不因为后来加了屏蔽词就看不见。
- 屏蔽只是隐藏，不删条目，也不改阅读状态。按 `id` 仍能取到和修改。改了屏蔽词马上生效，清空后条目重新出现。

## 设置接口

都要会话（设了口令时）。设置在 JSON 里是一个对象：

- `rsshubBaseUrl`：RSSHub 根地址，没设为空串。
- `retentionDays`：保留期限的天数，`0` 是永久。
- `aiBaseUrl`：OpenAI 兼容接口的根地址，例如 `https://api.openai.com/v1`，没设为空串。
- `aiModel`：模型名，没设为空串。
- `aiApiKeySet`：是否存了 API key。key 本身只能写（`PATCH` 的 `aiApiKey`），不下发。
- `aiLanguage`：摘要和翻译的目标语言，`zh-Hans` 或 `en`，默认 `zh-Hans`。
- `promptSummary`、`promptTranslate`：全局 prompt。没改过时是内置的默认 prompt。
- `defaultPromptSummary`、`defaultPromptTranslate`：内置的默认 prompt，只读，界面用它判断 prompt 改没改过、恢复默认。

| 路由 | 作用 |
|---|---|
| `GET /api/settings` | 当前设置。 |
| `PATCH /api/settings` | 改字段，只改请求里带的，返回改后的设置。 |

- `rsshubBaseUrl` 去掉首尾空白，空串表示不设；否则必须是带主机名的 http 或 https 绝对地址，可以指向本机或内网，不然 `invalid_rsshub_base_url`。
- `retentionDays` 是 0 到 3650 的整数，否则 `invalid_retention_days`；不是整数时 `invalid_body`。库里存的值读不成天数时按永久处理，返回 `0`（见「保留期限」）。
- `aiBaseUrl` 去掉首尾空白，空串表示不设；否则必须是带主机名的 http 或 https 绝对地址，可以指向本机或内网（例如本机的 Ollama），不然 `invalid_ai_base_url`。末尾的 `/` 去掉。
- `aiModel` 去掉首尾空白，最多 200 个字符，否则 `invalid_ai_model`。
- `aiApiKey` 去掉首尾空白后存下，空串表示删掉；最多 4096 个字符，否则 `invalid_ai_api_key`。本机的模型可以不要 key。
- `aiLanguage` 不是 `zh-Hans` 或 `en` 时 `invalid_ai_language`。
- `promptSummary`、`promptTranslate` 最多 4000 个字符，否则 `invalid_prompt`；空串（去掉首尾空白后）恢复内置的默认 prompt。
- 有一个字段不对就整个请求不生效。
- 抓取循环每次抓取和清理都重新读设置，改了从下一次抓取和清理起生效，不用重启。
- 只下发上面列出的字段。API key 一类的密钥不进任何响应、日志和错误，只回是否已配置。

## OPML 接口

都要会话（设了口令时）。

| 路由 | 作用 |
|---|---|
| `POST /api/opml/import` | 请求体是 OPML 文本，逐条添加订阅，返回 `{ "added": n, "existing": n, "failed": [...] }`。 |
| `GET /api/opml/export` | 所有源导出成一个 OPML 2.0 文件，`Content-Type: text/x-opml`，文件名 `oriel.opml`。 |

OPML 没有形态和 RSSHub 路径，Oriel 用 `outline` 上的两个自定义属性保留它们：`orielKind`（四种形态之一）和 `orielRsshubPath`。别的阅读器不认这两个属性，照常读 `xmlUrl`。

导入：

- 有 `xmlUrl` 或 `orielRsshubPath` 的 `outline` 是订阅，其余是分组。分组可以嵌套，逐层往下找；分组本身不导入。
- 有 `orielRsshubPath` 时按 RSSHub 源加，不看 `xmlUrl`；否则按 `xmlUrl` 加。没有 `orielKind` 时形态是 `article`。
- 标题取 `title`，没有就取 `text`，去掉首尾空白；和订阅地址一样时当没给，留给抓取补上。
- 每条按「订阅接口」添加的规则校验，抓取间隔用默认值。已经订阅了的（包括同一文件里重复出现的）计入 `existing`，不算失败。
- 不合规则的条目不影响别的条目，放进 `failed`，每项是 `{ "title", "address", "error" }`，`error` 是添加时的错误码，比如 `invalid_url`、`invalid_kind`。
- 文件最大 1 MiB，超了返回 413 `opml_too_large`；不是 XML、根元素不是 `opml` 时返回 400 `invalid_opml`，什么都不加。

导出：

- 每个源一个 `outline`，不分组，带 `text`、`title`、`type="rss"`、`xmlUrl`、`htmlUrl` 和 `orielKind`。标题为空时 `text` 用地址。
- RSSHub 源另带 `orielRsshubPath`。设了 RSSHub 根地址时，`xmlUrl` 是根地址加路径，别的阅读器能直接用；没设时没有 `xmlUrl`。
- 导出的文件再导入，得到同样的订阅：地址、RSSHub 路径、形态和标题都一样。别的字段（抓取间隔、prompt、屏蔽词、暂停）不导出。

## AI 摘要和翻译

摘要和翻译走用户自己的 OpenAI 兼容接口（`aiBaseUrl` 和 `aiModel` 都设了才算配置好）。都要会话（设了口令时）。

| 路由 | 作用 |
|---|---|
| `GET /api/entries/{id}/ai` | 条目的两种结果和当前的目标语言：`{ "summary": ..., "translation": ..., "targetLanguage": "zh-Hans" }`，没有的结果为 `null`。 |
| `POST /api/entries/{id}/summary` | 要摘要，返回这一种结果。 |
| `POST /api/entries/{id}/translation` | 要翻译，返回这一种结果。 |
| `POST /api/ai/test` | 用当前设置发一个很短的请求，成功返回 `{ "model": "..." }`；没配置好时 409，上游失败时 502，带下面的错误码。 |

一种结果是 `{ "status", "text", "error", "model", "updatedAt" }`，`status` 是 `pending`、`ok`、`failed`，`error` 只在 `failed` 时有值。

要结果（`POST`）：

- 没配置好时 409 `ai_not_configured`，条目不存在时 `not_found`。
- 已有 `ok` 的结果且指纹没变（模型、prompt、目标语言和原文都一样），直接返回，不调接口。
- 已经 `pending` 时直接返回，不重复排队。
- 其他情况（没有、失败过、指纹变了）排进队列，返回 202 和 `pending` 的结果；上一次成功的 `text` 留着，换成新结果前照样返回。客户端用 `GET /api/entries/{id}/ai` 轮询，建议每 2 秒一次。
- 用户要的不受自动重试的次数限制，每次 `POST` 都再试一次。

送去的原文：

- 第一行是条目标题，空一行，后面是正文的纯文本，段落之间空一行。正文依次取抽取的正文、订阅里的正文、订阅里的摘要，取第一个不为空的；都为空且没有标题时直接失败，`ai_empty`。
- 文章形态的条目还在等待抽取（`pending`）时先等抽取结束，再送。
- 摘要最多送 24 000 个字符，翻译最多 60 000 个字符，多出的截掉。
- 翻译按段落切成每块不超过 6000 个字符，一块一个请求，按顺序翻完再拼起来；有一块失败就整条失败。

调用：

- `POST {aiBaseUrl}/chat/completions`，`stream: false`。system 消息是生效的 prompt，user 消息是原文；设了 key 时带 `Authorization: Bearer <key>`。
- 生效的 prompt：源的 `promptSummary` / `promptTranslate` 不为空就用源的，否则用全局的。prompt 里的 `{language}` 换成目标语言的名字（`简体中文`、`English`）。
- 内置的摘要 prompt：`Summarize the article in {language} in three to five sentences. Reply with the summary only.`；翻译 prompt：`Translate the text into {language}. Keep the paragraphs and their order, and the title on the first line. Reply with the translation only.`
- 每个请求超时 120 秒，响应最大 1 MiB。认 `HTTP_PROXY` / `HTTPS_PROXY`。接口地址是用户自己填的，可以指向本机或内网，不走正文抽取的公网检查。
- 结果取第一个 `choices[].message.content`，去掉首尾空白；为空算失败。

失败的错误码（写进结果的 `error`，`POST /api/ai/test` 直接返回）：

| 代码 | 原因 |
|---|---|
| `ai_not_configured` | 没设接口地址或模型。 |
| `ai_unreachable` | 连不上（DNS、拒绝连接、TLS）。 |
| `ai_timeout` | 超时。 |
| `ai_unauthorized` | 上游 401 或 403，多半是 key 不对。 |
| `ai_rate_limited` | 上游 429。 |
| `ai_upstream` | 上游其他非 2xx，或返回的不是预期的 JSON，或结果为空。 |
| `ai_empty` | 条目没有可送的文字。 |

自动处理：

- 源开了 `autoSummary` / `autoTranslate` 时，抓取写入的新条目自动排队（`requested` 为 `0`）。只管打开开关之后新到的条目，不补旧条目。没配置好时不排。条目的语言已知且等于目标语言时不排自动翻译（见「语言检测」）；文章的语言要等抽取到全文才可能得知，之前排下的翻译照做。
- 后台一个处理器，同时最多 2 个请求。先做用户要的（新的在前），再做自动的（新的在前）。`POST` 排队后马上唤醒它，此外每 15 秒看一次队列。
- 自动的失败了按「满 3 次不再自动重试」处理，每次之间至少隔 5 分钟；不影响抓取和抽取。
- 设置改了之后，已有的结果不重做；下次用户要时指纹变了才重做。

日志只记条目 id、任务、模型、错误码和耗时，不记 key、prompt、原文和结果。

## 图片代理

`GET /api/image?url=<地址>` 替界面取缩略图、视频封面和条目里的图片。要会话（设了口令时）。界面不直接连这些地址：它们来自订阅内容，远程模式下客户端和服务端也不在同一个网络，地址检查只在服务端做一处。

- `url` 必须是带主机名的 http 或 https 绝对地址，否则 400 `invalid_url`。
- 按「正文抽取」的规则只连公网地址，超时 25 秒，重定向最多 5 次，直接连接不走代理。不带 `Referer`。
- 最大 8 MiB。按内容判断类型，只放行界面能解码的 PNG、JPEG、GIF、WebP 和 BMP。
- 已知的跟踪图片地址（见「正文显示」的图片规则）不去连，直接返回 502 `image_unavailable`，和被拦的地址一样；客户端本来就不会请求它们，这是给别的调用方挡一道。
- 连不上、地址被拦、上游不是 2xx、超过大小或类型不对，都返回 502 `image_unavailable`。
- SVG 不放行：它能带脚本，在服务端的源下打开时能读到会话 cookie；界面也解不了它。
- 成功时带判断出的 `Content-Type`、`X-Content-Type-Options: nosniff` 和 `Cache-Control: private, max-age=86400`。

图片缓存：

- 成功取到的图片存在数据目录的 `image-cache/` 里（用到时才建），一个地址一个文件，文件名是地址的 SHA-256 十六进制；文件里是内容类型、存入时间和图片字节。同一地址的下一次请求先读缓存，命中就不再连上游。
- 总量上限 256 MiB，有效期 30 天（从存入算起，命中不续期）。过期的文件按未命中处理，重新取后覆盖。
- 超过上限时按最近使用淘汰：命中会更新文件的访问时间，从最久没用的删起，删到上限的 90%。刚存入的那个不删。
- 只缓存通过上面全部检查的成功响应；失败（连不上、被拦、非 2xx、超大小、类型不对）不缓存。已知的跟踪图片地址在读缓存之前就拒绝，不会被缓存，也不会从缓存里返回。
- 写入先写同目录的临时文件再改名，崩溃不会留下半个文件被读到；启动后第一次用到时扫描目录，清掉遗留的临时文件，沿用已有的文件。读不出或格式不对的文件当作未命中并删掉。
- 缓存只是加速：随时可以删掉整个 `image-cache/` 目录，下次请求会重新取。

- 选一个形态只看这种形态的条目，下面的订阅列表也只列这种形态的源；选一个订阅只看它，它所属形态的按钮保持高亮；再选「全部」回到混合时间线。
- 最下面是服务端栏：本机显示「本机」，远程显示主机名，点了打开连接界面（见「连接远程服务端」）。
- 「订阅」标题右边是添加按钮，没有订阅时也在。有订阅抓取失败时，标题和添加按钮之间多一个警告色的「N 个失败」，点它侧栏只列出失败的订阅，标题换成「抓取失败」，右边是「显示全部」；点「显示全部」、选别的形态或失败的都恢复后回到原来的列表。右键一个订阅弹出菜单：更新（失败的订阅叫「重试」）、把订阅标为已读、编辑…、暂停或恢复、删除…（见「订阅管理」）。「把订阅标为已读」在这个订阅有未读（`unreadCount` 大于 0，暂停的也算）时可用，不分当前看的是什么范围；不弹确认，发 `POST /api/entries/read`，带 `sourceId`、不带 `upTo`，订阅里这一刻所有的未读都标掉。成功后出提示条，同「全部标为已读」。

工具栏：当前范围的标题和未读数，选了一个订阅时标题后面有编辑按钮；「全部 / 未读 / 收藏」三段（对应 `unread=1`、`starred=1`）；检索框；「全部标为已读」。

- 检索框停止输入 300 毫秒后检索，回车立即检索，Esc 清空。去掉首尾空白后不到 3 个字时不发请求，在工具栏下面提示「至少输入 3 个字才能搜索」，列表保持原样。检索时标题旁显示结果数（已加载的条数，还有下一页时带「+」）。
- 「全部标为已读」只在「全部」和「未读」下、没有检索、当前范围有未读时可用。不弹确认，直接发 `POST /api/entries/read`，`upTo` 是已加载的最上面那条，打开列表之后新到的条目仍是未读。成功后底部出提示条「已把“〈范围〉”里的 N 条标为已读」，带「撤销」和关闭按钮；提示条消失之前，点「撤销」或按 Cmd/Ctrl+Z 用返回的 `ids` 发 `POST /api/entries/unread`，列表和未读数改回去。再做一次「全部标为已读」时，上一次就不能撤销了。
- 右键列表里的一个条目弹出菜单：收藏或取消收藏、标为已读或标为未读、在浏览器中打开，和行上的按钮一样（菜单是系统自己的，只有文字）；分隔线下面是「把上面的标为已读」。「上面」是当前列表里排在这个条目前面的、已加载的条目，不含这个条目自己：发 `POST /api/entries/read`，`newerThan` 是这个条目，`upTo` 是已加载的最上面那条，带当前范围的 `sourceId` 或 `kind`，打开列表之后新到的条目仍是未读。上面没有未读（包括它就是第一条）时灰掉；在「收藏」下或检索时也灰掉，因为接口按范围标，不认收藏和检索的筛选。成功后出提示条「已把上面的 N 条标为已读」，N 是返回的 `marked`。「全部标为已读」「把上面的标为已读」「把订阅标为已读」的提示条一样：带「撤销」和关闭按钮，Cmd/Ctrl+Z 撤销，按返回的 `ids` 发 `POST /api/entries/unread`；三者共用一个撤销，新做一次，上一次就不能撤销了。「把订阅标为已读」的提示条是「已把“〈订阅〉”里的 N 条标为已读」。
- 按 V 把当前窗口里看得见的条目标为已读，并把窗口滚到它们下面的第一条，选中和焦点也落在那一条上，一键清掉一屏。只在「全部」和「未读」下、没有检索时有效，条件同「把上面的标为已读」，不弹确认；检索框有焦点、对话框或阅读器开着、焦点在侧边栏时不起作用。
  - 「看得见」指整行（视频是整张卡片，图片是整块）都在列表区域里的条目，列表区域不含盖在上面的工具栏；被上边缘或下边缘切掉一截的不算，留作未读，滚动后成为窗口最上面的一条。范围是从第一条完全看得见的到最后一条完全看得见的，按列表顺序。视频网格按整行算；图片是瀑布流，各列高低不一，所以从第一条完全看得见的往后数，数到第一条没有完全看得见的为止（它和它后面的不标），中间被滚到上边缘之外的不管。
  - 发 `POST /api/entries/read`：`upTo` 是范围里最上面那条，`newerThan` 是范围后面紧跟的那条（也就是滚到最上面的那条），带当前范围的 `sourceId` 或 `kind`，范围外的未读不动。已加载的最后一条完全看得见、但后面还有下一页时，它不进范围（后面没有可以当 `newerThan` 的条目），留作未读并成为滚到最上面的那条，下一页照常加载，再按一次即可；已经没有下一页时，范围到列表末尾，不带 `newerThan`，窗口停在末尾，选中落在范围里最后一条。
  - 范围里已经是已读的条目不动，也不计入 N。范围里一条未读也没有时不发请求、不出提示条，只滚动，所以 V 也能当翻页键用；列表载入中、没有一条完全看得见（一行比窗口还高）、或在「收藏」和检索下，什么也不做。
  - 成功后出提示条「已把可见的 N 条标为已读」，N 是返回的 `marked`；带「撤销」和关闭按钮，Cmd/Ctrl+Z 撤销，与「全部标为已读」等共用同一个撤销。滚动立即发生，不等请求；请求失败时提示「没能保存改动」（同其他标已读的失败），列表位置不回退。
  - 触控板滑动翻页做不到：MyGo 0.5.5 没有手势回调，只做键盘，滑动留作以后。

列表：

- 每页 50 条，按游标翻页，滚到离底部不到 10 条时取下一页；取失败时底部显示重试。
- 「全部」「文章」「社交」和单个订阅用一列，每行按条目的形态画：文章是标题、来源和时间、两行摘要，有缩略图时放右边；视频是 16:9 封面加时长；社交是作者、正文（最多 6 行）配图，不超过一行：一张按自己的比例，两张并排成 4:3，三张或更多只显示前三张，排成一行方图，多出的数量写在第三张上「+N」；图片是一张 3:2 的大图。
- 「视频」用封面网格，「图片」用瀑布流：按图片的宽高放进当前最矮的一列，没有宽高时按 4:3。
- 未读的条目左边有一个强调色圆点，标题加粗；已读的标题变淡。
- 时间显示为相对时间（「5 分钟前」「3 小时前」「昨天」「3 天前」），一周以前显示日期，不是今年时带年份。用 `publishedAt`，没有就用 `createdAt`。
- 图片经图片代理取，在后台解码，同时最多取 4 张；内存里缓存最近解码过的图，取失败的显示占位底色，不再重试，直到重新加载。

打开条目：点一行（或回车）同时标为已读；文章在列表的位置打开阅读器（见「阅读器」），视频、社交和图片用系统浏览器打开条目链接。行上悬停或选中时右上角显示收藏、已读/未读切换和在浏览器中打开三个按钮，文章也可以这样直接去浏览器。改状态先改界面，请求失败时改回来并提示。

新条目：每 60 秒在后台重新取一次订阅列表和当前范围的第一页。有比列表最上面那条更新的条目时，列表不动，顶部出现「N 条新内容」，点了重新加载并回到顶部；N 只数第一页里的，最多 50。检索时不检查新条目。

切换保留：在内存里保留最近看过的 8 个列表（范围加筛选），每个记下已加载的全部条目、滚动位置和选中的条目；切回时立刻画出，再在后台重新取第一页，用新的第一页加上缓存里比它更旧的条目合并，按 `id` 去重，选中的条目和滚动位置不动，新条目插在上面。检索结果不保留；换了服务端、登录失效或重新加载整个列表时清空；全部标为已读后，保留的未读列表不再带着这些条目。

后台检查失败（列表已经加载过，订阅列表或第一页取不到）时，列表照常留着、照常能用，工具栏下面多一行安静的状态「连不上服务端 · 上次更新于 10:42」，时间是最近一次检查成功的时刻；服务端栏的圆点同时从绿色变成警告色。下一次检查成功后这一行消失、圆点变回绿色。这一行对读屏软件播报一次，之后的检查接着失败不再重复播报。

空状态：没有订阅时提示「还没有订阅」，说明里加一句可以填 RSS 地址、也可以直接贴 YouTube、X、GitHub、哔哩哔哩、微博和 Telegram 的链接，下面是「添加第一个订阅」按钮和旁边的「导入 OPML…」，后者打开设置的「导入与导出」；「未读」下没有条目时显示「都读完了」；检索没有结果时显示「没有找到“…”」；第一页取不到时显示「时间线加载不出来」和重试按钮。会话失效（401）时打开连接界面。

键盘：

- ↑ ↓ 或 J K 在条目间移动，N 跳到选中那条下面的下一条未读（已加载的走完了先取下一页，再没有时提示「下面没有未读了」，选中不动），回车或 O 打开，S 收藏或取消，M 切换已读，V 把看得见的标为已读并滚到下面的第一条（见上面「把可见的标为已读」一条），`/` 把焦点移到检索框，Cmd/Ctrl+N 添加订阅，`?` 或 Cmd/Ctrl+/ 打开键位表（「帮助」菜单里也有「键盘快捷键」）。对话框开着时这些键不起作用。阅读器开着时用阅读器的键（见「阅读器」）。
- 侧边栏也能用键盘到达：1 到 5 切到「全部」和四种形态（文章、视频、社交、图片，顺序同侧边栏），在时间线的任何位置都行；H 或 ← 把焦点移到侧边栏当前选中的那一项（范围是某个订阅时就是那个订阅），↑ ↓ 在形态和订阅间移动（移到某个形态就切到它，订阅要按回车才选中），焦点留在原处，L、→ 或 Esc 把焦点交回列表、回到选中的那一条（还没选过就选第一条）。焦点在侧边栏时，J K O S M N V 和 ↑ ↓ 不动条目，`/` 照样去检索框。Shift+F10 或键盘上的菜单键打开焦点所在订阅或条目的右键菜单（Mac 键盘没有菜单键，只有 Shift+F10；笔记本要加 fn），菜单项和右键相同。这些键都列在键位表里，检索框有焦点、对话框开着、阅读器开着时都不起作用。用键盘切换范围时，对读屏软件播报「视频，12 条未读」这样的话，焦点不移动。
- 每一行对辅助技术读作「来源、标题、时间、未读或已读、收藏」；收藏、标为已读、全部标为已读、把可见的标为已读（提示条的文字，随后读到新选中的那一条）、加载完和出错都用播报告知。

### 阅读器

文章在列表的位置打开，左栏留着；经 `GET /api/entries/{id}` 取正文，界面不碰存储。

- 工具栏：左边「回到〈范围〉」；右边上一篇、下一篇、摘要、翻译、收藏、已读/未读切换、在浏览器中打开。上一篇、下一篇只在当前列表里的文章之间走，跳过别的形态；下一篇走到已加载的最后一篇时先取下一页。正文还没取到或取不到时，收藏、已读切换和在浏览器中打开不可用。
- 页面：来源和时间（完整日期加时刻，不是今年时带年份），标题，再是正文，中号字时最宽 680，随阅读文字大小增减（见偏好）。正文开头和标题相同的标题行去掉。
- 文章打开后，阅读器在后台预取列表里前一篇和后一篇的正文和已有的摘要、翻译（只读，从不请求生成），放进最多 3 篇的小缓存（当前一篇加两个邻居，按最近使用淘汰）；J、K 走到预取过的文章时立即显示正文，不出现加载状态，摘要和翻译仍照常重新读取。预取失败不提示，只是那一步照旧等待。换服务器、换范围或筛选、重新加载列表时缓存清空；不预取图片。
- 打开时标为已读，已读切换可以撤销。点左栏、换「全部 / 未读 / 收藏」或检索都会关上阅读器。

状态，按 `extractStatus` 和带不带正文分：

- 全文：`ok` 且抽出的正文不为空，只显示正文。
- 只有 RSS 正文：抽取失败（或这个条目不抽），显示订阅里带的正文（没有正文就用摘要），上面一条警告色提示「这不是全文」，带「打开原文」链接。
- 正在取全文：`pending` 时先显示 RSS 正文，提示正在取全文；连 RSS 正文也没有时显示「正在取全文」和「打开原文」按钮。每 5 秒重新取一次，`ok` 了就换成全文并播报「全文已载入」；中途取失败保持原样，不报错。
- 抽取失败也没有 RSS 正文：显示「没有可显示的正文」和「打开原文」按钮。
- 取不到条目：显示「这篇加载不出来」和重试按钮。会话失效（401）时打开连接界面。

摘要和翻译，经「AI 摘要和翻译」的接口：

- 打开文章时取一次 `GET /api/entries/{id}/ai`，已有的摘要直接显示，已有的译文不自动换上。
- 「摘要」是开关：按下发 `POST .../summary`，标题下面出一张卡片；再按收起。卡片在生成时显示「正在生成摘要…」和「取消」，生成好显示摘要和「由〈模型〉生成」，失败显示原因（按错误码，见「AI 接口」）和「重试」。
- 条目的语言（`language`）等于目标语言（`targetLanguage`）时没有「翻译」按钮，已经开始的翻译除外；语言为空或不同则照常显示。目标语言取自第一次 `GET .../ai` 的回答，回答到之前按钮先显示。
- 「翻译」也是开关：按下发 `POST .../translation`。生成时原文照常显示，标题下面一条提示「正在翻译，好了之前先看原文」和「取消」；好了之后标题和正文换成译文，提示「由〈模型〉翻译」，带「译文 | 原文」切换；失败时原文不动，提示原因和「重试」。译文是纯文本段落，第一行是标题；图片和链接只在原文里。
- 进行中时每 2 秒取一次 `GET .../ai`。「取消」和离开这篇文章只是不再等，服务端的处理照常做完，下次打开时就有结果。
- 没配置 AI（`ai_not_configured`）时，按摘要或翻译出一张卡片「还没配置 AI」，带「打开设置…」，打开设置的 AI 组。

正文在客户端从 HTML 画成原生视图，不用 WebView：

- 画：标题（h1、h2 一级，h3 到 h6 一级）、段落、换行、有序和无序列表（含嵌套和 `start`）、引用块、代码块（保留换行，横向滚动）、行内代码、粗体、斜体、删除线、链接、图片和图注、分隔线；表格每行一段，单元格之间用「·」隔开。
- 不画：脚本、样式、表单、iframe、object、embed、svg、math、视频、音频、canvas。
- 链接：相对地址按条目链接补全；只留 http、https 和 mailto，页内锚点和 `javascript:` 只留文字。点了用系统浏览器打开。
- 图片：`src` 为空或是 data URI 时用 `data-src`。计数用的图片不画，也不去取，免得告诉对方这篇被打开了：宽或高不超过 2 像素的；带 `hidden` 属性的；行内 `style` 里 `display:none`、`visibility:hidden`，或 `width`、`height`、`max-width`、`max-height` 为 0 或不超过 1 像素的；地址属于已知跟踪图片的。已知跟踪图片的清单写在代码里（`internal/tracker/`），不联网更新，只按主机后缀和路径前缀匹配，不看查询串，不拦这些主机上的普通图片（`i0.wp.com`、`substackcdn.com`、list-manage.com 的 logo 照常显示）：`google-analytics.com`、`doubleclick.net`、`googletagmanager.com`、`pixel.wp.com`、`stats.wordpress.com`、`feedsportal.com`、`track.hubspot.com` 整个主机；feedburner 的 `/~r/`、`/~ff/`；邮件服务的打开像素：list-manage.com 和 mandrillapp.com 的 `/track/open`、sendgrid.net 的 `/wf/open`、mailgun.org 的 `/o/`、pstmrk.it 的 `/open`、ConvertKit 的 `open.convertkit-mail*` 和 `open.kit-mail*`；任何主机上的 `/__utm.gif`、`/__ptq.gif` 和 `/api/v1/email/open`（Substack 的打开像素）。只在显示时过滤：条目存的 `content` 仍是原始 HTML，抓取时不改写，接口给别的调用方的也是原文。经图片代理取，在后台解码，按正文顺序同时最多取 4 张；按 `width`、`height` 留出位置，没有时按图片本身，取到之前按 16:9；取失败的不显示。

键盘：J K 上一篇、下一篇，N 下一篇未读（只在当前列表里找，跳过别的形态，再没有时提示「后面没有未读文章了」，留在这篇），S 收藏，M 切换已读，O 在浏览器中打开，Esc 回到列表，焦点回到那一行。焦点在正文上，方向键、空格、PageUp/PageDown、Home/End 滚动；Tab 依次经过正文里的链接。正文可以选中复制。播报「全文已载入」和出错。

### 订阅管理

都经「订阅接口」和「设置接口」，界面不碰存储。

添加：侧栏的添加按钮、没有订阅时的「添加第一个订阅」和 Cmd/Ctrl+N 打开添加对话框。字段是地址、形态、标题（可空，空就用订阅里的）和检查间隔（15 分钟、30 分钟、1 小时、3 小时、6 小时、12 小时、1 天，默认 15 分钟）。

- 地址框边输入边识别，在框下面说清会订阅什么（平台和对象，加上实际的订阅地址或路由），发请求之前就能看到；服务端照样再查一遍。识别出的平台带出形态，用户自己选过形态之后就不再改。
- 以 `/` 开头、不以 `//` 开头的是 RSSHub 路由。以设置里的 RSSHub 根地址开头的完整地址存成路由（去掉根地址），以后换实例只改设置。
- 别的必须是带主机名的 `http://` 或 `https://` 地址；不是时点「添加」才在框下面报错，把焦点放回地址框，改了地址错误就消失。
- 要存成路由、而设置里还没有 RSSHub 根地址时，框下面提示先填根地址，多一个根地址的输入框。点「添加」先存设置，再加订阅；根地址不对时报在根地址框下面。
- 已经订阅过（409 `source_exists`）时提示「已经订阅过了，叫“…”」，带「去看看」，点了关掉对话框、选中那个订阅。连不上服务端时在对话框里提示，不关对话框。
- 加好后关掉对话框，订阅出现在侧栏，提示「已添加“…”」。条目由抓取循环去抓，随时间线的定时检查出现。

平台链接的识别（主机名去掉 `www.` 和 `m.`）：

| 填的地址 | 订阅 | 形态 |
|---|---|---|
| `youtube.com/channel/<id>` | `https://www.youtube.com/feeds/videos.xml?channel_id=<id>` | `video` |
| `youtube.com/@<handle>` | 路由 `/youtube/user/@<handle>` | `video` |
| `youtube.com/playlist?list=<id>` | `https://www.youtube.com/feeds/videos.xml?playlist_id=<id>` | `video` |
| `space.bilibili.com/<uid>` | 路由 `/bilibili/user/video/<uid>` | `video` |
| `x.com/<name>`、`twitter.com/<name>` | 路由 `/twitter/user/<name>` | `social` |
| `github.com/<owner>/<repo>` | `https://github.com/<owner>/<repo>/releases.atom` | `article` |
| `github.com/<owner>` | `https://github.com/<owner>.atom` | `article` |
| `t.me/<name>`、`t.me/s/<name>` | 路由 `/telegram/channel/<name>` | `social` |
| `weibo.com/u/<uid>`、`weibo.com/<uid>`（数字） | 路由 `/weibo/user/<uid>` | `social` |

X 的 `home`、`i`、`search`、`explore`、`settings`、`messages`、`notifications` 等站内页面不算用户名。路径以 `.atom`、`.rss`、`.xml` 结尾的本来就是订阅，不再转换。别的地址原样当订阅地址。

修改：右键菜单的「编辑…」或工具栏的编辑按钮打开编辑对话框。最上面一行是抓取状况：「5 分钟前检查过 · 10 分钟后再查」，还没抓过时「还没检查过」，失败时「连续失败 N 次：原因」，暂停时「已暂停，恢复之前不抓取」，旁边是「更新」（失败时叫「重试」，暂停时没有）。下面是标题、检查间隔、形态、暂停开关和屏蔽词（每行一个）。「保存」只发改了的字段。订阅地址不能改。最后一组是「摘要和翻译」：「自动生成摘要」「自动翻译」两个开关（只管打开之后新到的条目），和摘要、翻译两个 prompt 框，留空就用设置里的 prompt。没配置 AI 时这一组上面多一行「还没配置 AI，暂时不会生成摘要和翻译」，带「打开设置…」。

暂停和恢复：右键菜单或编辑对话框的开关，发 `PATCH` 改 `paused`。

更新：右键菜单或编辑对话框的「更新」（失败的订阅叫「重试」，做的事一样），发 `POST /api/sources/{id}/refresh`，提示「已排进抓取」；新条目随定时检查出现。

删除：右键菜单或编辑对话框的「删除…」先弹确认窗口：「删除“…”？它的条目会一起删掉，收藏的也是。删了不能恢复。」确认后发 `DELETE`，从侧栏去掉；正看着它时回到「全部」。

出错：请求失败时提示原因，对话框不关；会话失效（401）时打开连接界面。

### 设置界面

都经「设置接口」「OPML 接口」和会话接口，界面不碰存储。除「外观」外，设置属于服务端，连到同一个服务端的设备看到的一样；「外观」是这台设备自己的偏好，存在本机，不经服务端（见下面「外观」）。

打开：时间线服务端栏旁边的齿轮，或应用菜单的「设置…」（Cmd/Ctrl+,）。连接界面显示时不打开。左上角「回到时间线」和 Esc 回到时间线，时间线保持原样。侧栏分五组：外观、抓取、导入和导出、AI、设备，外观排第一；底部的服务端栏只说明是哪个服务端的设置，点了不换服务端。每次打开重新读取设置和设备；读不出来时显示「设置加载不出来」和「重试」。

外观：

- 页面顶上一行说明：这些只对这台设备生效。其他几组的页面说明是设置存在服务端、对连到它的每台设备都生效。
- 偏好存在数据目录里的 `preferences.json`，和 `remote.json` 并列，只有当前用户能读写（0600）；是客户端自己的文件，不进服务端的 `/api/settings`，所以每台设备各有一份。连接界面的「本机」按钮删掉的只是 `remote.json`，偏好保留。文件不存在、读不出来或有认不得的值时，对应项用默认值，不报错。
- 主题：跟随系统（默认）、浅色、深色。强调色是青绿，两种主题下都一样。选了立即生效。
- 界面语言：跟随系统（默认）、简体中文、English，语言名用它自己的语言写。跟随系统时，中文系统（含繁体）显示简体中文，其他系统显示英文。选了立即生效，不用重启：各界面原地换成新语言，时间线的范围、选中的条目、列表位置和打开的文章、设置停在的分组都保持不变。界面还是只有这两种语言。原生更新窗口和启动失败的错误框在界面之外弹出，仍然用系统语言。
- 界面字体：系统字体（默认），或者一个已安装的字体族。列表来自 MyGo 的 `ui.FontFamilies()`（系统已安装的字体族，按字母排序，不分大小写）。设置里是一个按钮，点开是带搜索框的弹出列表（docs/design.md 的字体选择器）：「系统字体」和当前选的字体族固定在最上面，其余按字母排；输入时不分大小写、名字里任意位置匹配，匹配不到就显示「没有匹配…的字体」；每个字体名用它自己的字体显示；列表在后台取，取到之前只有固定的行和一行「正在读取字体…」。键盘：上下键移动，回车选定，Esc 关闭并回到按钮。选的字体族后来被卸载了，就退回系统字体，偏好里的值保留。字体族设在主题的 `Font` 上，所有界面文字都用它，包括阅读窗格的正文（阅读字体为「跟随界面」时）；等宽的内容（代码块、接口地址框）不变。界面文字大小仍然跟随系统的文字缩放，不是设置。
- 阅读字体：跟随界面（默认）、衬线，或一个已安装的字体族，只改阅读窗格里文章的正文；标题、笔记、二级和三级标题、说明文字和工具栏仍用界面字体，代码仍是等宽。设置里的按钮和界面字体一样，点开是同一个字体选择器，「跟随界面」和「衬线」固定在最上面，当前选的字体族接在后面（见上面的界面字体），其余按字母排。「衬线」是平台的一组衬线字体：macOS 用 New York 配宋体-简（Songti SC），Windows 用 Georgia 配宋体（SimSun），Linux 用 Noto Serif 配 Noto Serif CJK SC；一个都没装就用界面字体。选的字体族后来被卸载了，就退回跟随界面，偏好里的值保留。默认仍是界面字体，因为细的衬线字在屏幕上发虚。设置里「阅读」卡片的示例段落用选中的字体显示。
- 阅读文字大小：小、中（默认）、大、特大，只改阅读窗格的正文和跟它成比例的标题、代码；时间线、侧栏和其他界面不变。阅读窗格的正文栏宽跟着文字大小走：680 乘以字号比例，小、中、大、特大依次约 635、680、771、861，每行的字数基本不变；窗口放不下时仍以窗口为限。没有单独的宽度设置。
- 行距：紧凑、标准（默认）、宽松，只改阅读窗格的正文。
- 中文排版：开（默认）或关，一个开关，放在「阅读」卡片里行距之后，只对这台设备生效。开时，对中文文章（条目存的语言以 `zh` 开头；没存语言时看正文里有没有汉字）做两件事：汉字和西文字母、数字之间留 0.25em 的间隙，连续的全角标点压缩（如 `」。` 占 1.5em 而不是 2em）。间隙是字间距，不插入字符，所以复制、搜索拿到的仍是原文。范围是阅读窗格里的标题、二级和三级标题、正文、列表、引用、图注、说明、AI 摘要和翻译；代码、时间线和其他界面不受影响。行首行尾的标点悬挂和避头尾由平台的文字排版决定，暂不处理（docs/design.md 的「Chinese typesetting」）。行距和段间距不随开关变化，中文用的是行距里较大的那组数值。
- 具体数值见 `design/tokens.md`。每一项选了就存，立即生效；存不上时退回原来的值并提示。

抓取：

- RSSHub 实例：等宽输入框，改了之后「保存」变成主按钮，点它或按 Enter 发 `PATCH`。服务端拒绝（`invalid_rsshub_base_url`）时框下面报错，焦点留在框里，改了错误就消失；连不上时提示「没能保存」。存好后框里换成服务端规整过的地址，提示「下次抓取起生效」。
- 条目保留：永久、1 周、1 个月、3 个月、半年、1 年；服务端存的是别的天数时，多一项「N 天」。选了就存，存不上时退回原来的值并提示。

导入和导出：

- 导入：「选择文件…」打开系统的文件对话框（OPML 和 XML 文件）。在后台读文件，超过 1 MB 不发，直接提示；发 `POST /api/opml/import`，进行中显示「正在导入 …」。结果留在按钮下面：新增几个、已经订阅几个、几个没能添加，没能添加的逐条列出标题、地址和原因；不是 OPML（`invalid_opml`）、太大（`opml_too_large`）、读不出来和连不上各有提示。新增了订阅时，时间线重新读取订阅和条目。结果可以关掉。
- 导出：「存储为…」打开系统的保存对话框，默认文件名 `Oriel.opml`；在后台取 `GET /api/opml/export` 写进文件，提示导出了几个订阅（带 `xmlUrl` 或 `orielRsshubPath` 的 `outline`），写不进去和连不上各有提示。

AI：

- 接口地址、模型、API key 和输出语言在一张卡片里，一个「保存」，只发改了的字段。服务端拒绝时错误显示在对应的框下面，焦点留在那个框里。
- API key 不回显：框总是空的，旁边标「已配置」或「未配置」。填了就替换旧的；已配置时有「移除 key」，发空串删掉。
- 「测试」发 `POST /api/ai/test`，用的是已保存的设置，所以有没保存的修改时不可用，提示「先保存再测试」。进行中显示「正在发一个简短的请求…」，成功显示「已连通，〈模型〉有回应」，失败按错误码提示原因。
- 摘要 prompt 和翻译 prompt 在另一张卡片里，各有「恢复默认」（就是默认时不可用），一个「保存」。下面说明 `{language}` 会换成上面的输出语言，每个订阅可以在编辑对话框里用自己的 prompt。

设备：

- 用口令登录过的服务端列出 `GET /api/sessions` 的会话，当前设备排第一、标「本设备」。名字从 User-Agent 来：桌面应用是「Oriel · macOS」，浏览器是「Safari · iPhone」这样的浏览器和平台，认不出时显示原文，空的显示「未知设备」。下面一行是登录日期和最近使用时间。
- 别的设备有「退出登录…」，先确认，确认后发 `DELETE /api/sessions/{id}`，从列表去掉；已经不在了（404）也去掉。
- 本机没有口令的服务端没有设备，说明连到设了口令的服务端后才会列出。

会话失效（401）时打开连接界面。

窗口默认 960×640，最小 640×480，用 Oriel 自己的配色（暖灰和青绿，见 `design/tokens.md`），图标用 Lucide。

## 更新

用 MyGo 的原生更新插件（`native.Plugin`）。更新源只有 `yangflow/oriel` 公开的 GitHub Releases，走 HTTPS；每个平台一份更新清单，安装包和增量包都用 Ed25519 签名，公钥写在 `mygo.json` 的 `updates.publicKey`，签名不对、换了密钥或不是 HTTPS 的更新一律不装，应用保持原样。

- 每天在后台检查一次，应用菜单「检查更新…」随时检查。
- 有新版本时弹原生更新窗口，显示这一版在 `CHANGELOG.md` 里的说明，用户选安装、跳过这一版或以后提醒；不确认就不下载、不安装。
- 窗口的语言跟随系统，不受「外观」里界面语言的影响：中文系统（含繁体）显示简体中文，其他系统显示英文。
- 开发构建（`go tool mygo dev`）和没有用发布密钥签过的构建不检查更新。`oriel serve` 不更新自己。

发布流程、密钥和每次发布的步骤见 [docs/release.md](release.md)。

## 技术基线

Go 1.27.1，MyGo v0.4.1，SQLite 用纯 Go 的 `modernc.org/sqlite`，生产代码不用 cgo，没有前端工具链。macOS 12+、Windows 10/11、带 GTK 3 的 Linux，amd64 和 arm64。Linux 程序需要 glibc（MyGo 动态加载系统库），无窗口模式也一样：可以跑在不带 GTK 的 Debian 等系统上，但不能跑在 Alpine 等 musl 系统上。界面只有简体中文和英文：默认跟随系统，中文系统（含繁体）显示简体中文，其他系统显示英文，也可以在「外观」里固定其中一种。没在真机上测过的性能不写进文档。
